# 《见好不收》交互系统实施报告

实施日期：2026-08-24

## 实施范围

按“输入与转场 → 移动与碰撞 → 世界交互 → 摄像机 → 对话与 UI → 清理 → 观察 → 性能与回归”的顺序完成。本轮不改变剧情目标、文物结论、处置逻辑或现有美术方向。

## 新交互架构

- `InputActionManager`：场景级输入队列、130ms 缓冲、145ms 默认防重复、输入上下文、失焦清理、监听器生命周期。
- `PointerGestureSession`：捕获拖动指针，并在画布外松开、取消、失焦、隐藏、Scene Shutdown 时统一结束手势。
- `InteractionController`：交互目标评分、250ms 粘滞、目标确认/距离不足反馈。
- `SceneTransitionController`：单次转场锁、200–350ms 过渡、真实加载超过 200ms 后显示“拓片显影”进度、耗时记录。
- `InteractionDebugOverlay`：仅开发环境启用，F8 切换 FPS、速度、输入、目标、碰撞体、Dead Zone、监听器和转场耗时。

## 浏览器实测

测试环境：Chrome、1280×720、Vite 开发服务器。

- 50ms 时移动速度已经达到约 80–103 px/s，动画进入行走态。
- 直线速度 165 px/s；斜向速度 165 px/s；倍率 1.000。
- 松开方向键后约 101–117ms 完全停止。
- 页面失焦后速度立即归零，动画恢复 idle。
- 玩家停止后摄像机 220ms 采样位移为 0px。
- Scene 重启前后键盘 `keydown` 监听器均为 2，没有累积。
- 连续快速触发 30 次 E：队列最终清空，Scene 与任务阶段不变，没有重复转场或多次执行。
- 清理时触发 `gameout` 后拖动状态为 false。
- 观察时在 Canvas 外触发 `pointerup` 后拖动状态为 false。
- 主菜单确认到剧情 Scene 可操作实测 315–322ms。
- 文物清理：快速拖动连续，祭祀钱错误竹签操作产生 44.78 损伤并破坏 `ritual-facing` 证据。
- 文物观察：线装册两条不同条件证据均可记录；侧光提示可正常进入下一步。
- 自动化运行期间无 page error / console error。

详细机器结果：`artifacts/interaction-refactor/results.json`、`artifacts/restoration-refactor/playtest-results.json`、`artifacts/click-move/results.json`。

## 已知风险

- 当前生产包仍是单个约 1.54MB JS chunk；不影响本轮交互正确性，但首次网络加载仍应后续做代码分包。
- 物理墙角测试已覆盖常用店内与墓穴路线，但所有特殊装饰碰撞仍建议人工完整走一遍。
- 自动化环境的实际 FPS 高于显示器刷新率，不能替代低端设备和高 DPI 显示器的人工帧时间测试。
- 本机缺少 Playwright FFmpeg 运行件，在线安装在环境中超时，因此本轮没有生成 WebM；自动化指标与截图仍已保存。
